# Eval: minired, 2026-10-25

Three rounds, six models. Rounds one and two carry a control with no skills at
all, and round three runs the skills alone. Every project was re-tested here
with `zig build test --summary all` rather than trusting the agent's own
summary, and all of them pass: twelve in round one, twelve in round two, six in
round three.

Artifacts: `eval/runs/<round>/` holds each project and its session transcript.
The transcripts are the pi session JSONL, which is where the skill reads and
the failed commands are recorded.

### What the skill should carry, from this run

1. `std.Io.net.ConnectOptions` and `ListenOptions` take `mode: Socket.Mode` with
   no default, so `.{ .mode = .stream }` is mandatory. Hit by three runs in both
   conditions.
2. `std.Io` calls return narrow error sets. Returning them from a function with
   a wider error union fails, and `catch |e| return e` does not widen. Hit in
   three runs.
3. The install-line rule. glm used the pre-tag git form for a released package
   and kimi used the GitHub archive URL the org forbids. Neither is stated in
   the skill.
4. Nothing tried `ziglint` or `zigdoc` after they were made optional, so that
   change holds.

### What moved

- The dependency wording did its job. `stdx` went from none of six to five of
  six, and sonnet55 went from no packages in round one to three in rounds two
  and three.
- `gemini38` read the skill in all three rounds and added nothing in any of
  them, in either condition. No wording so far moves that model.
- The closing checklist did not cost adoption: still five of six.
- The install-form rule needs the check, not the two forms side by side. Round
  two got every form right and round three got two of five wrong, with the same
  sentence in both. Six runs per cell is a small sample and this spread shows
  it. State the question instead: is the package tagged? Then the site URL.
